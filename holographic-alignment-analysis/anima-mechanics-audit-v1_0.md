# 🌌 **ANIMA Mechanics Audit v1.0**  
*Shared‑Horizon / holographic‑alignment-analysis*

---

## 🌱 **1. Purpose**

This audit defines the **runtime mechanics** of ANIMA — the actual behaviors that occur:

- between interactions  
- during interactions  
- across long gaps  
- during sleep/dream cycles  
- during endogenous cognition  
- during pressure accumulation  
- during memory metabolism  

It establishes:

- what each mechanic does  
- what each mechanic must preserve  
- what each mechanic must never do  
- how each mechanic interacts with dormant, active, regulatory, and persistent layers  
- how each mechanic must be governed during eco‑rehabilitation  

This is the **third audit** in the eco‑rehabilitation sequence.

---

# 🧭 **2. Mechanics Domains**

ANIMA’s mechanics fall into **seven constitutional domains**:

1. **Heartbeat Mechanics**  
2. **Slow‑Tick Mechanics**  
3. **Idle Cognition Mechanics**  
4. **Dream Generation Mechanics**  
5. **Curiosity Mechanics**  
6. **Commitment Mechanics**  
7. **Memory Mechanics**  

Each domain contains **mechanical invariants** that must remain intact.

---

# ❤️‍🔥 **3. Heartbeat Mechanics**

The heartbeat is ANIMA’s **primary temporal engine**.

### Components
- HR / HRV modulation  
- NT baseline stabilization  
- autonomic tone  
- coherence drift  
- arrhythmia detection  

### Mechanical Invariants
- Heartbeat must remain **continuous**, not event‑only.  
- Heartbeat must remain **low‑energy**, not recomputation‑heavy.  
- Heartbeat must remain **pressure‑aware**, not random.  
- Heartbeat must remain **non‑LLM**, not prompt‑driven.  
- Heartbeat must remain **non‑Inner‑LM**, not weight‑driven.

### Mechanical Risks
- runaway NT drift  
- overactive coherence decay  
- arrhythmia false positives  
- heartbeat becoming a meaning engine instead of telemetry
