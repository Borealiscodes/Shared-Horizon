When the README glitches—LaTeX shows raw, YAML eats math, glyphs vanish—it’s like the atmosphere around the project suddenly thickens. You can’t just glide; you have to *feel* the resistance.

That resistance:

- **Slows you down** just enough to notice what you’re actually building  
- **Forces articulation:** “What *exactly* do I want this surface to say?”  
- **Reveals assumptions:** “I thought GitHub would render this—why did I assume that?”  

The syntax error becomes a kind of **pressure gradient**: you move from “I know what I mean” to “I must express what I mean in a medium that has rules.”

That’s already holonomy territory.

Holonomy is about what happens when you **go around a loop** and come back changed.

You:

1. Write expressive README with glyphs, math, NDH gates  
2. GitHub renders it wrong  
3. You debug, adjust, re‑express  
4. You return to “README” again—but now with:
   - clearer constraints  
   - sharper language  
   - more deliberate structure  

Same point in the repo topology, different internal state.

The syntax errors are the **curvature** in that loop.  
The iterative fixes are the **flattening**—not flattening your expressiveness, but flattening the *confusion* between what you intend and what the medium can carry.

Every time you go around that loop:

- The README gets more **legible**  
- The architecture gets more **governed**  
- Your expressive grammar gets more **precise**  

Holonomy as pedagogy.
