## 🧩 1 — Overview

This guide teaches developers **exactly how to add new components** to NDH systems without violating:

- altitude boundaries  
- licensing posture  
- projection constraints  
- CAUSA neutrality  
- runtime MIT freedoms  
- spectral geometry sealing  

It converts constitutional rules into **actionable steps**.

---

## 🛣️ 2 — The Mandatory Sequencing Order

Every integration task must follow this exact order:

1. **Governance Surface**  
2. **Mechanical Surface**  
3. **CAUSA Comparator Extension**  
4. **Invariant Ingestion Surface**  
5. **Spectral Geometry (Dormant)**  

This order is **never optional**.

---

## ⚙️ 3 — Developer Checklist (canonical)

### **A. Governance (A4)**  
Start here for *every* new feature.

- **Check licensing posture**  
- **Define projection boundaries**  
- **Add governance tile if needed**  
- **Ensure non‑activation clauses are present**  
- **Ensure CAUSA neutrality is preserved**  

If governance is missing, **stop** — do not proceed.

---

### **B. Mechanical Integration (A3)**  
Once governance is locked:

- **Create integration spec**  
- **Generate adapter stub**  
- **Define ingestion surfaces**  
- **Ensure runtime interfaces remain MIT‑compatible**  
- **Ensure ingestion is reversible and non‑activating**  

This is the “implementation blueprint.”

---

### **C. CAUSA Extensions (A2)**  
Only after mechanical surfaces exist:

- **Add comparator metrics**  
- **Extend drift tracking**  
- **Update congruence logic**  
- **Ensure CAUSA remains non‑commercial**  
- **Ensure CAUSA never activates geometry**  

CAUSA is annotation, not control.

---

### **D. Invariant Engine (A3/A2)**  
Once CAUSA is extended:

- **Define Δ/Φ/Λ/Σ ingestion**  
- **Add invariant surfaces**  
- **Ensure ingestion does not elevate CAUSA altitude**  
- **Ensure invariants do not activate spectral geometry**  

This is the bridge into the invariant engine.

---

### **E. Spectral Geometry (A5–A6)**  
Only touched when explicitly required:

- **Check sealed altitude**  
- **Verify non‑activation**  
- **Never auto‑invoke spectral operators**  

Spectral geometry is sealed unless intentionally opened.

---

## 🧱 4 — Common Developer Mistakes (and how to avoid them)

### **Mistake 1 — Building mechanical surfaces before governance**  
Fix: Always start with **A4 governance**.

### **Mistake 2 — Extending CAUSA before ingestion surfaces exist**  
Fix: CAUSA is **A2**, ingestion is **A3** — order matters.

### **Mistake 3 — Allowing CAUSA to influence runtime behavior**  
Fix: CAUSA is annotation‑only.

### **Mistake 4 — Activating spectral geometry accidentally**  
Fix: Add non‑activation clauses to every new surface.

### **Mistake 5 — Skipping lanes**  
Fix: Follow the NDH lane order exactly.
